### 3. CONTENÇÃO DO VOICESTUDIO: CERTIFICAÇÃO DUPLA (CLIENTE + SERVIDOR)

A contenção do VoiceStudio foi validada em duas camadas estritas:

1. **Camada de Apresentação (Frontend - PR #43):**
   - Refatoração de `src/services/voice/aeternumVitaConfig.js`.
   - `isVitaVoiceEnabled(targetUser)` adota arquitetura *fail-closed default-deny*: retorna `false` a menos que exista a claim explícita `voice_enabled === true`, `is_voice_pilot === true` ou `voice_entitlement === "active"` no `app_metadata` emitido pelo servidor.
   - Tentativas de forjamento no cliente (`user_metadata`, token alterado) são ignoradas.
   - Mensagem de erro alinhada em `src/services/voice/aeternumLiveKitService.js`: `"O recurso VoiceStudio não está habilitado para esta conta. Acesso restrito a participantes autorizados do programa piloto."`.

2. **Camada de Autorização (Servidor - Edge Function `voice-token`):**
   - Chamada anônima: rejeitada com HTTP 401 `AUTH_REQUIRED`.
   - Chamada autenticada de estudante sem entitlement: rejeitada com HTTP 403 `VOICESTUDIO_NOT_PERMITTED`.
   - Chamada com bypass injetado em `user_metadata`: sumariamente rejeitada com HTTP 403 `VOICESTUDIO_NOT_PERMITTED`.
   - Usuário participante de piloto com entitlement em `app_metadata`: autorização confirmada.
