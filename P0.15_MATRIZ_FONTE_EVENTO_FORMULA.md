## 2. MATRIZ EXAUSTIVA DE INDICADORES

### Indicador 1: Progresso Geral do Estudante (Strategic Donut)
- **Localização:** `src/components/Analytics/StrategicProgressDonut.jsx` e `src/pages/dashboard/Dashboard.jsx`.
- **Rótulo no Dashboard:** `Progresso Geral` (dentro de card com título errôneo `Desempenho por sistema`).
- **Fonte Atual:**
  - Horas 3D: `viewer_learning_sessions` (apenas `scope = 'viewer'`).
  - Flashcards: `localStorage.getItem('aeternum-flashcards-v1')` ou `viewer_learning_events`.
  - Quizzes: `viewer_quiz_results` (apenas notas 100%).
  - Tutor IA: `localStorage.getItem('atlas-tutor-session-history')` ou `viewer_learning_events`.
- **Fórmula Atual:**
  $$P_1 = \min\left(100, \frac{\text{Horas 3D}}{48} \times 100\right)$$
  $$P_2 = \min\left(100, \frac{\text{Cards Revisados}}{100} \times 100\right)$$
  $$P_3 = \min\left(100, \frac{\text{Quizzes com 100\%}}{6} \times 100\right)$$
  $$P_4 = \min\left(100, \frac{\text{Perguntas ao Tutor}}{500} \times 100\right)$$
  $$\text{Progresso Geral} = \frac{P_1 + P_2 + P_3 + P_4}{4}$$
- **Problema Diagnosticado:**
  - Média linear de metas arbitrárias sem base pedagógica.
  - Exige 48h de tela 3D e 500 perguntas de chat. Estimula volume vazio e spam mecânico.
  - Quizzes só contam se a pontuação for 100% perfeita. Qualquer acerto entre 70% e 99% é descartado e vale 0.
- **Fórmula Proposta (Índice de Maturação Curricular $I_{\text{maturação}}$):**
  $$I_{\text{maturação}} = \sum_{s \in \text{Sistemas}} w_s \cdot M_{\text{sistema}}(s)$$
  Onde $w_s$ é o peso relativo do sistema anatômico no semestre do estudante (ex: Anatomia I = Locomotor 40%, Cardiovascular 30%, Respiratório 30%) e $M_{\text{sistema}}$ é a maestria no sistema baseada em evidências observadas. Se um sistema não foi iniciado, é exibido explicitamente como *Não Iniciado*, sem imputação artificial de metas globais de 500 perguntas.

### Indicador 2: Tempo de Estudo Semanal / Mensal / Anual
- **Localização:** `src/features/dashboard/components/WeeklyStudyChart.jsx` e `src/services/learningMetrics.js` (`buildStudySeries`).
- **Rótulo no Dashboard:** `Tempo de estudo semanal`, `0 minutos no período`, cápsulas diárias (qui, sex, sáb...).
- **Fonte Atual:** Tabela `viewer_learning_sessions`.
- **Evento Gerador:** `learning_session_started`, `learning_session_ended`, `heartbeat`.
- **Fórmula Atual:**
  $$\text{Filtro estrito:} \quad \text{sessão.scope} === 'viewer'$$
  $$\text{Minutos no dia } d = \sum_{s \in S_d, \text{scope}='viewer'} \frac{\text{normalizedActiveSeconds}(s)}{60}$$
  $$\text{Altura da barra no gráfico} = \frac{\text{Minutos do dia } d}{\max_{k}(\text{Minutos do dia } k)} \times 100$$
- **Problema Diagnosticado:**
  - **Descarta 87,5% de todas as sessões reais do aluno** (2.151 de 2.458 sessões) porque o Tutor IA, Flashcards e Quizzes no app web recebem `scope = 'account'`.
  - Resulta no infame `0 MIN` para estudantes altamente engajados.
  - A altura relativa das barras faz com que 5 minutos pareçam uma barra cheia de 100% caso o dia anterior tenha tido 0 minutos (escala flutuante sem referência temporal fixa).
- **Fórmula Proposta (Tempo Ativo Unificado Qualificado $T_{\text{ativo}}$):**
  $$T_{\text{ativo}}(u, \Delta t) = \sum_{s \in S(u, \Delta t)} t_{\text{qualificado}}(s)$$
  $$t_{\text{qualificado}}(s) = \min\Big(\text{active\_seconds}(s), \; \text{duration\_seconds}(s), \; 14.400\text{s}\Big)$$
  - **Inclusão obrigatória de todos os escopos:** `scope IN ('viewer', 'account', 'flashcards', 'quiz', 'tutor')`.
  - **Subtração de inatividade:** `active_seconds` monitorado por detecção de foco da janela (`visibilitychange`), eventos de mouse/toque no canvas 3D e digitação no Tutor IA. Sessões sem heartbeat por mais de 180s são congeladas.
  - **Apresentação no Gráfico:** Exibir horas absolutas no eixo Y (ex: 0h, 1h, 2h, 4h) com distinção cromática por modalidade:
    - Azul Esmeralda: *Exploração 3D & Dissecção Virtual*.
    - Púrpura A26: *Retenção Ativa & Flashcards*.
    - Ouro Âmbar: *Diálogo com Tutor IA & Síntese Clínica*.
    - Coral: *Simulados Anatômicos*.

### Indicador 3: Desempenho por Sistema Anatômico
- **Localização:** `src/services/learningMetrics.js` (`buildSystemLearningMetrics`, linhas 188–245) e `src/features/dashboard/components/EvolutionPanel.jsx`.
- **Rótulo no Dashboard:** `Pontos fortes` e `Pontos a revisar`.
- **Fonte Atual:**
  - Catálogo de modelos (`models.js`).
  - `viewer_learning_events` (`annotation_selected`).
  - `viewer_quiz_results` (`score`).
  - `localStorage` (`aeternum_completed_models`).
- **Fórmula Atual:**
  $$\text{Cascata de fallback:}$$
  $$\text{Se total de questões respondidas} > 0 \implies \text{percentual} = \frac{\text{Acertos no Quiz}}{\text{Questões}} \times 100 \quad (\text{tipo: 'quiz'})$$
  $$\text{Senão, se anotações clicadas} > 0 \implies \text{percentual} = \frac{\text{Anotações Vistas}}{\text{Total Anotações}} \times 100 \quad (\text{tipo: 'annotations'})$$
  $$\text{Senão, se modelos existem} \implies \text{percentual} = \frac{\text{Modelos Concluídos}}{\text{Total Modelos}} \times 100 \quad (\text{tipo: 'completion'})$$
  $$\text{Senão} \implies \text{percentual} = 0$$
- **Problema Diagnosticado:**
  - **Incomensurabilidade categórica:** Uma nota de 80% em prova difícil é misturada na mesma lista que um estudante ter clicado em 80% das legendas 3D ou ter marcado 80% dos modelos no checkbox manual.
  - **Classificação bizarra de extremos:** Se o aluno estudou apenas o Sistema Cardiovascular e teve 80%, esse sistema aparece simultaneamente nos "Pontos Fortes" (maior nota) e "Pontos a Revisar" (única nota), gerando uma contradição visual direta na interface.
- **Fórmula Proposta (Tríade de Maestria Anatômica por Sistema):**
  Para cada sistema anatômico $s$, a plataforma não gera um único número ilusório, mas uma **Tríade Pedagógica Transparente**:
  1. **Cobertura Estrutural 3D ($C_{\text{estrutural}}$):**
     $$C_{\text{estrutural}}(s) = \frac{|\text{Estruturas Únicas Dissecadas / Inspecionadas no 3D}|}{|\text{Total de Estruturas Chave Cadastradas do Sistema}|} \times 100\%$$
  2. **Retenção Ativa SRS ($R_{\text{SRS}}$):**
     $$R_{\text{SRS}}(s) = \frac{|\text{Flashcards no Estágio Consolidado (Intervalo } \ge 7 \text{ dias)}|}{|\text{Total de Cards Ativos do Sistema}|} \times 100\%$$
  3. **Acurácia em Simulados Clínicos ($A_{\text{simulados}}$):**
     $$A_{\text{simulados}}(s) = \frac{\sum_{i \in \text{Quizzes}(s)} \text{acertos}_i}{\sum_{i \in \text{Quizzes}(s)} \text{questões}_i} \times 100\%$$
     *(Caso o estudante ainda não tenha realizado simulados daquele sistema, o campo exibe explicitamente `Simulado Pendente`, sem aplicar fallback enganoso).*

### Indicador 4: Modelos Concluídos (Cards de Resumo)
- **Localização:** `src/pages/student/StudentLearningPage.jsx` (`/progress` e `/academic-reports`).
- **Rótulo no Dashboard:** `MODELOS CONCLUÍDOS: 1 (33%)`.
- **Fonte Atual:** Exclusivamente `localStorage.getItem('aeternum_completed_models')`.
- **Fórmula Atual:**
  $$\text{Percentual} = \frac{\text{Array.isArray(saved) ? saved.length : 0}}{\text{catalogModels.length}} \times 100$$
- **Problema Diagnosticado:**
  - Armazenado puramente no navegador local. Ao mudar de aba, dispositivo ou limpar dados de navegação, o número volta a `0`.
  - Ação manual sem verificação: o aluno simplesmente clica num botão "Marcar como estudado" sem qualquer evidência de tempo de leitura, exploração das estruturas ou fixação.
  - O catálogo total é inferido localmente (`catalogModels.length`), gerando denominadores inconsistentes (ex: 3 modelos mockados = 33%).
- **Fórmula Proposta (Conclusão Verificada de Módulos 3D):**
  Um modelo só recebe o selo de `Módulo Exploratório Concluído` no Supabase (`user_model_progress`) quando atende a 3 critérios empíricos objetivos:
  $$\text{Concluído}(u, m) \iff \begin{cases}
  T_{\text{ativo}}(u, m) \ge T_{\text{mínimo}}(m) \quad (\text{ex: } 10 \text{ minutos}) \\
  \text{Cobertura de Estruturas}(u, m) \ge 75\% \\
  \text{Autoavaliação ou Quiz de Fixação Concluído} \ge 60\%
  \end{cases}$$
  Persistência sincronizada com RLS na tabela `user_model_progress` no Supabase com sincronização offline transparente via IndexedDB.

### Indicador 5: Continuidade por Sistema (Tabela de Barras em `/progress`)
- **Localização:** `src/pages/student/StudentLearningPage.jsx` (linhas 410–475).
- **Rótulo no Dashboard:** `CONTINUIDADE POR SISTEMA: Sistema anatômico 0/0, Sistema Cardiovascular 0/1...`
- **Fonte Atual:** Combinação de `progressService.getCompletedModelIds()` (local) e metadados de modelos.
- **Fórmula Atual:**
  $$\text{Razão} = \frac{\text{modelosEstudadosNoSistema}}{\text{totalModelosNoSistema}}$$
  $$\text{Largura da Barra} = \text{clamp}\left(\frac{\text{modelosEstudados}}{\text{totalModelos}} \times 100, 0, 100\right)$$
- **Problema Diagnosticado:**
  - **Bug da Divisão por Zero:** Para "Sistema anatômico" (categoria genérica ou órfã), `totalModelos = 0`. A divisão `0 / 0` resulta em `NaN`. O cálculo de CSS gera uma barra anômala de ~60% de preenchimento (comprovado no screenshot `p0_15_page_academic_reports.png`).
  - Lista sistemas sem modelos cadastrados (`0/0` e `0/1`), transmitindo sensação de produto incompleto ou catálogo vazio.
- **Fórmula Proposta:**
  - Tratamento estrito de divisão por zero:
    $$\text{Se } \text{total} \le 0 \implies \text{Exibir estado vazio: "Nenhum modelo cadastrado neste sistema" (barra em 0% ou oculta)}.$$
  - Exibir barra segmentada em 3 fases: *Estruturas 3D Inspecionadas*, *Casos Clínicos Discutidos* e *Simulado Realizado*.

### Indicador 6: Métricas de Interação com Tutor IA
- **Localização:** `src/pages/dashboard/Dashboard.jsx` (`tutorQuestionsCount`, linhas 96–107).
- **Rótulo no Dashboard:** `Tutor IA & Síntese: 0% (0 / 500)`.
- **Fonte Atual:** `localStorage.getItem('atlas-tutor-session-history')` ou fallback para eventos `tutor_question` em `viewer_learning_events`.
- **Fórmula Atual:**
  $$\text{Contagem} = \text{mensagens com sender === 'user' ou role === 'user'}$$
  $$\text{Percentual} = \min\left(100, \frac{\text{Contagem}}{500} \times 100\right)$$
- **Problema Diagnosticado:**
  - O banco Supabase já possui as tabelas `ai_conversations` (210 conversas) e `ai_messages` (534 mensagens reais de 6 estudantes). O frontend ignora essas tabelas e busca no `localStorage`!
  - Uma meta de 500 perguntas é gigantesca e arbitrária para um estudante de graduação. Um aluno que faz 3 perguntas profundas e obtém respostas de alto nível clínico recebe `3/500 = 0,6%` de progresso, parecendo insignificante.
- **Fórmula Proposta (Índice de Profundidade Dialógica $D_{\text{clínica}}$):**
  Em vez de contar mensagens brutas, calcular:
  1. *Casos Clínicos & Dúvidas Debatidas:* `count(DISTINCT conversation_id)`.
  2. *Domínios Anatômicos Invocados:* sistemas mapeados nas conversas via anotações semânticas da Edge Function `ai-tutor` (`context->'structures'`).
  3. *Taxa de Resolução:* conversas marcadas pelo estudante como "Dúvida Esclarecida" ou salvas em "Minhas Notas".

## 3. ESQUEMA DE DADOS PROPOSTO PARA O SUPABASE (EXPAND/CONTRACT)

Para dar suporte às fórmulas acima sem romper compatibilidade com o frontend atual, a modelagem de banco de dados para a Missão P0.16 adotará as seguintes estruturas relacionais no schema `public`:

### A. Tabela Unificada de Progresso do Modelo: `user_model_progress`
```sql
CREATE TABLE IF NOT EXISTS public.user_model_progress (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id UUID NOT NULL REFERENCES auth.users(id) ON DELETE CASCADE,
  model_id TEXT NOT NULL,
  system_id TEXT NOT NULL, -- ex: 'cardiovascular', 'nervous', 'locomotor'
  active_study_seconds INTEGER NOT NULL DEFAULT 0,
  structures_explored_count INTEGER NOT NULL DEFAULT 0,
  structures_total_count INTEGER NOT NULL DEFAULT 0,
  exploration_completed BOOLEAN NOT NULL DEFAULT FALSE,
  is_favorite BOOLEAN NOT NULL DEFAULT FALSE,
  notes_count INTEGER NOT NULL DEFAULT 0,
  last_accessed_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  UNIQUE (user_id, model_id)
);
```

## 4. CONCLUSÃO DA MATRIZ

A aplicação destas definições encerra definitivamente a era das metas arbitrárias (48h/500 perguntas), elimina a dependência frágil de `localStorage` e substitui o fallback misto por uma **Tríade de Maestria Anatômica Transparente**, devolvendo a credibilidade científica aos relatórios acadêmicos da Aeternum Atlas.
