## 1. O INCIDENTE COMPROVADO EM PRODUÇÃO

Ao acionar a funcionalidade **"✨ Explicar com Tutor IA"** em um flashcard sobre o tema **Plexo Braquial**, o estudante recebeu uma resposta totalmente inadequada ao propósito de aula explicativa:

1. **Formato Incompatível com a Interface de Conversação:**
   - A resposta foi transmitida como um bloco de código `json` contendo um array de objetos: `[{"front": "...", "back": "...", "explanation": "...", "learningObjective": "..."}]`.
   - Delimitadores técnicos como `}]` e crases triplas vazaram no fluxo de texto do chat do Tutor.

2. **Falácias Anatômicas Graves:**
   - **4 Troncos em vez de 3:** O modelo afirmou categoricamente a existência de "quatro troncos" no plexo braquial.
   - **Tronco Costocervical como Nervo:** O tronco costocervical (que é um tronco arterial clássico derivado da primeira ou segunda porção da artéria subclávia) foi categorizado como um tronco nervoso formador do plexo braquial.
   - **Inervação Motora do Trapézio:** A motricidade do músculo trapézio foi atribuída ao fascículo lateral ou ao plexo braquial, quando canonicamente a inervação motora é exercida pelo Nervo Acessório (NC XI), recebendo dos ramos C3-C4 do plexo cervical apenas aferências proprioceptivas.
   - **Paralisia de Erb-Duchenne:** A lesão clássica de Erb-Duchenne (avulsão/tração do tronco superior C5-C6) foi erroneamente associada à lesão isolada do fascículo lateral.

## 2. ANÁLISE DE CAUSA-RAIZ (TRACE COMPLETO DO PIPELINE)

O diagnóstico empírico e estático no repositório revelou **quatro falhas encadeadas** que criavam uma armadilha epistêmica para o modelo neural:

### Falha 1: Ambiguidade de Origem no Frontend (`AnatomicalFlashcardsPage.jsx`)
No método original `handleExplainWithAI(card)`:
```javascript
openTutor({
  prompt,
  context: {
    source: "flashcards", // <- AMBIGUIDADE CRÍTICA
    route: "/flashcards",
    topic: card.topic,
    difficulty: card.difficulty || activeDeck?.difficulty,
    cardId: card.id,
    learningObjective: card.learningObjective || null,
    language: langKey
  },
  contextLabel: `Flashcards · ${card.topic}`
});
```
O contexto transmitia `source: "flashcards"` sem especificar `task: "explain_flashcard"`. Todo o backend interpretava `source: "flashcards"` como sendo uma ordem para gerar um novo baralho de flashcards em formato JSON.

### Falha 2: Indução de Premissa Falsa no Prompt de Usuário
O prompt original transmitia a pergunta e a resposta do cartão sem isolamento semântico:
```text
Pergunta: "Quais são os quatro troncos do plexo braquial?" Resposta: "O plexo braquial possui quatro troncos..."
```
Sem instrução explícita de verificação de hipótese, o modelo tratava o texto como premissa verdadeira aceita pelo usuário e prosseguia gerando uma resposta concordante com a falácia.

### Falha 3: Injeção Incondicional de Schema JSON na Edge Function (`ai-tutor/index.ts`)
Nas linhas 1529-1531 da Edge Function `ai-tutor`:
```typescript
} else if (context.source === "flashcards" || payload.task === "generate_flashcards" || task === "generate_flashcards") {
  sysInstructionText += "\n\nModo de saída — Flashcards Anatômicos:\nResponda SOMENTE com um array JSON válido contendo os objetos flashcard [{\"front\": \"...\", \"back\": \"...\", \"explanation\": \"...\", \"learningObjective\": \"...\"}], sem introdução, sem conclusão e sem blocos Markdown.";
}
```
Como `context.source === "flashcards"`, o prompt de sistema do LLM recebia a ordem estrita de responder **exclusivamente com um array JSON**.
Além disso, a lista de tarefas permitidas `ALLOWED_OPERATIONAL_TASKS` continha apenas `["generate_flashcards", "generate_mind_map", "tutor_ia", "anatomical_quiz", "socratic_case"]`, omitindo completamente `explain_flashcard`.

### Falha 4: Desativação do Raciocínio Clínico no Gateway Local (`OllamaLLMProvider.ts`)
No provedor local Ollama, a função `resolveOllamaReasoningParams` classificava qualquer requisição com `source === "flashcards"` como tarefa estruturada rápida:
```typescript
const isStructuredTask = source === "flashcards" || ...;
if (isStructuredTask) {
  return { reasoning_effort: "none", think: false };
}
```
Ao desligar o raciocínio profundo do Qwen 3.5 4B (`think: false`), o modelo perdia a capacidade de conduzir a reflexão metacognitiva necessária para detectar a falsidade da premissa e refutá-la.

## 3. A ARQUITETURA CORRETIVA IMPLEMENTADA

A Missão Master P0.20-G substituiu a ambiguidade por contratos explícitos e independentes:

```
[ Flashcard: Explicar com IA ]
            │
            ▼
{ task: "explain_flashcard", source: "flashcard-explanation", originModule: "flashcards" }
            │
            ├───────────────────────────────────────────────────────┐
            ▼                                                       ▼
[ Backend / Edge Function ]                               [ Gateway Local / Ollama ]
• ALLOWED_OPERATIONAL_TASKS.has("explain_flashcard")     • isStructuredTask = FALSE
• isGenerationTask = FALSE                               • reasoning_effort = default ({})
• Prompt Didático Especializado:                         • Raciocínio clínico ativo
  - Trata o cartão como proposição a verificar
  - Refutação obrigatória de premissas falsas
  - Estrutura Markdown (TA2, Sintopia, Clínica)
  - Proibição estrita de JSON
            │                                                       │
            └─────────────────────────┬─────────────────────────────┘
                                      ▼
                      [ Interceptor de Resposta ]
                      • Se receber JSON bruto:
                        - Não renderiza JSON na tela
                        - Emite TUTOR_RESPONSE_CONTRACT_MISMATCH
                        - Executa 1 retry seguro ou fallback didático
                                      ▼
                   [ Aula Anatômica Clara e Rigorosa ]
```

## 4. VERIFICAÇÃO DE EFICÁCIA

A correção foi auditada e comprovada através da suíte determinística `test_p0_20_g_explanation.mjs` executando diretamente sobre o modelo `qwen3.5:4b`:

| Critério | Antes da P0.20-G | Após a P0.20-G |
| :--- | :--- | :--- |
| **Formato de Saída** | Array JSON bruto `[{"front": ...}]` | Texto didático em Markdown acadêmico com seções estruturadas |
| **Raciocínio Qwen** | `think: false` (desativado) | Raciocínio profundo ativo (`reasoning_effort: {}`) |
| **Detecção de 4 Troncos** | Normalizou o erro, aceitando 4 troncos | **Rejeitou explicitamente:** declarou que o plexo tem estritamente 3 troncos |
| **Tronco Costocervical** | Apresentou como nervo do plexo braquial | **Rejeitou categoricamente:** esclareceu que é artéria da subclávia |
| **Inervação do Trapézio** | Atribuída ao fascículo lateral | **Corrigida:** atribuída exclusivamente ao Nervo Acessório (NC XI) |
| **Paralisia de Erb** | Associada ao fascículo lateral | **Corrigida:** associada ao tronco superior (raízes C5-C6) |
| **Geração de Baralhos** | Funcionava | **100% Preservada:** `generate_flashcards` continua gerando JSON em ~12s |

A causa-raiz foi extirpada na arquitetura, garantindo que o Tutor IA atue verdadeiramente como um professor titular de anatomia digital.
